# RANI AI — Android only

**Scope: Android only. Windows is dropped** (the original desktop app
was a Windows PyQt5 app; RANI does not ship a Windows build).
iOS was dropped by the user — no iOS work in this project.

The original Python code cannot become a native Android app directly, so RANI
is built the BADSHAH way: **one phone web app, wrapped for Android.**

```
rani-web/      → the real app (voice, chat, vision, website builder, PWA)
android/       → Android WebView wrapper (package com.badshah222.rani.ai)
```

## Run the web app locally

```bash
cd rani-web
python3 -m http.server 8080
# open http://localhost:8080
```

- Copy `rani-web/js/config.example.js` → `rani-web/js/config.js` and add
  your own Gemini / Supabase / Firebase keys (placeholders only in the
  repo). Without a key the app runs in demo mode and says so.
- On the phone, the same folder can be hosted (e.g. Cloudflare Pages,
  `rani-ai-girlfrind.pages.dev`) and opened in any mobile browser. It is also an
  installable PWA (manifest + service worker): browser menu → "Add to
  Home screen" / "Install app".
- Camera vision needs `https` (or `localhost`); screen vision
  (`getDisplayMedia`) works in Chrome on Android 14+ via the wrapper's
  WebView only where the system allows it — test on a real phone.

## How the Android APK builds (CI)

1. Push to `main` (or open a PR) touching `android/`, `rani-web/`, or the
   workflow file.
2. GitHub Actions (`.github/workflows/android-build.yml`) builds a
   **debug APK on every run** — no secrets needed. Download it from the
   run's Artifacts (`rani-ai-debug-apk`).
3. A **signed release APK** is built only when all four signing secrets
   exist in the repo (Settings → Secrets and variables → Actions):
   `ANDROID_KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`,
   `KEY_PASSWORD`.

### Pushing the workflow file — read this

The GitHub connector **cannot push `.github/workflows/*` files (403)**.
This workflow file is delivered in the repo tree; push it via the browser
(github.com web upload) or git from a machine with repo access.

### Release keystore — none is committed

**No keystore file exists in this repo, and none must be committed.**
Create one at release time:

```bash
keytool -genkeypair -v -keystore rani-release.keystore -alias rani \
  -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 rani-release.keystore   # store the output as ANDROID_KEYSTORE_BASE64
```

Keep the original keystore file somewhere safe (not in the repo, not in
chat). If it is lost, the app can never be updated under the same package
name again — a new listing would be needed.

### Local debug build

```bash
cd android
./gradlew assembleDebug
# APK: app/build/outputs/apk/debug/app-debug.apk
```

Needs Android SDK + JDK 17. The wrapper loads the web app from
`MainActivity.APP_URL` (default `https://rani-ai-girlfrind.pages.dev` — change at
release time); if the site is unreachable it shows a bundled offline page.
The `gradlew` launcher script is generated by Android Studio / `gradle wrapper`
(the wrapper properties are in the repo).

## What is NOT in this build

- No Windows `.exe` / PyInstaller build (dropped by scope).
- No native rewrite of the original Python features (PC control, floating orb
  over other apps, system hotkeys) — those are desktop-only and have no
  phone equivalent in this version. Phone features are: voice chat, text
  chat, camera + screen vision, website builder, settings.
- No APK file is produced or claimed by this task — the APK is produced
  by CI after push.
